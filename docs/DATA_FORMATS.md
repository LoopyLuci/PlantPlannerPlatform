# DATA_FORMATS.md: every stored format

Every format here is a contract. A breaking change needs an ADR and a migration. Every
durable format has a plain-text form that can be read without this software.

## Versioning rule

Each format has a schema string. A **major** change is breaking and needs an ADR and a migration. A **minor** change is additive and needs a CHANGELOG entry. A **patch** changes documentation only.

## 1. Design event log: `data/designs/<design_id>.ndjson`

One JSON object per line. Lines are appended, never edited.

| Field | Type | Meaning |
|---|---|---|
| `seq` | integer | 1-based position in the log. Must equal the line number. |
| `ts` | string | ISO 8601 UTC timestamp of the write |
| `type` | string | `DesignCreated`, `SiteUpdated`, `PlacementAdded`, `PlacementUpdated`, `PlacementRemoved`, `DesignArchived` |
| `actor` | object | `{ id, interface }`, for example `{ "id": "local-user", "interface": "api" }` |
| `idempotency_key` | string or null | The key the client sent. Replays return the event that holds it. |
| `payload` | object | Type-specific data. Camel-case field names, matching the code. |
| `prev_hash` | string | Hash of the previous event. 64 zeros for the first event. |
| `hash` | string | SHA-256 of the input below, in lower-case hex |

**Hash input:**

```
hash = sha256( prev_hash + "\n" + canonical_json({seq, ts, type, actor, idempotency_key, payload}) )
```

`canonical_json` sorts object keys recursively and drops `undefined`. To verify by hand, recompute this for each line in order and compare with `hash`.

**Torn tail:** a final line that does not parse, with no newline after it, is an interrupted write. It is not part of the chain. The next write moves it to `<design_id>.torn-<epoch-ms>.txt` and continues.

## 2. Snapshot: `data/designs/<design_id>.snapshot.json`

```json
{
  "schema": "ppp-snapshot-1",
  "design_id": "d_...",
  "offset": 18,
  "head_hash": "<hash of event 18>",
  "state": { "...the projected design..." },
  "state_hash": "<sha256 of canonical_json(state)>",
  "created_at": "2026-11-01T00:00:00.000Z"
}
```

A snapshot is used only if three checks pass: its state matches its own `state_hash`; `offset` is in range; and event `offset` has `head_hash`. Verification also replays the log to `offset` and compares the state hash.

## 3. Knowledge graph: `data/knowledge-graph/`

CSV (RFC 4180) plus `manifest.json`. Field definitions are in `data/knowledge-graph/SCHEMA.md`.

| File | One row per | Key columns |
|---|---|---|
| `manifest.json` | graph | `graph_version`, `status`, `license` |
| `species.csv` | species | `urn`, `scientific_name`, `common_name`, `family`, `growth_form`, `guild_layer` |
| `traits.csv` | trait value | `urn`, `trait`, `value`, `unit`, `source_id`, `grade` |
| `companion_edges.csv` | relationship | `species_a_urn`, `species_b_urn`, `mechanism`, `direction`, `source_id`, `grade`, `note` |
| `sources.csv` | citation | `source_id`, `title`, `author`, `year`, `url`, `archive_url`, `license`, `citation_status`, `grade` |

Build-time rules (enforced): every trait and edge cites a known source; grades are A, B or C; trait names come from a fixed list; URNs match `urn:ppp:species:<slug>`.

## 4. Plain-text archive: `data/archive/` (`archive-1`)

Generated by `npm run archive`. Layout:

```
README.md                         how to read the archive, with no software
knowledge-graph/                  copies of the CSV, manifest and SCHEMA.md
designs/<design_id>/design.json   name, archived flag, head sequence, site, graph version
designs/<design_id>/placements.csv
designs/<design_id>/placements.geojson   local site metres, not GPS (CRS named in the file)
designs/<design_id>/events.ndjson        copy of the full log, hashes included
feedback/feedback.ndjson          copy of the feedback log (section 8), hashes included
feedback/feedback.csv             one row per feedback entry, with the route it was sent to
feedback/README.md                what the feedback files are
rules/rules-<version>.json        the rule thresholds in use (section 9)
checksums.sha256                  sha256sum format; verify with `sha256sum -c`
```

The archive export refuses to run if the feedback chain is broken, the same way a broken design log stops a read.
`data/archive/` is generated. Do not edit it by hand.

## 5. Registry definitions

Each capability in `packages/registry/src/capabilities.ts` declares: `id`, `title`, `description`, `input` (field specs with type, required, enum, range, default), `output` (prose), `sideEffect`, `determinism`, `scopes`, `atomicity`, `idempotencyRequired`, `reloadClass`, `recoveryBehavior`, `webSupport`, and `exposure` (api, cli, mcp, web). `validateRegistry()` checks these.

## 6. API envelope

Every capability response has this shape:

```json
{
  "ok": true,
  "capability": "design.evaluate",
  "data": { "...": "..." },
  "version": { "modelVersion": "none", "graphVersion": "kg-2026.10", "ruleConfigVersion": "rules-1.0" },
  "provenance": { "interface": "api", "actor": "local-user" },
  "idempotency": null
}
```

Failures have `ok: false` and `error: { code, message, details?, issues? }`. Error codes: `validation_error` (400), `idempotency_key_required` (400), `confirmation_required` (400), `not_found` (404), `unknown_capability` (404), `conflict` (409), `integrity_error` (500), `internal_error` (500). The CLI maps the same codes to exit codes 2, 2, 2, 1, 1, 4, 5 and 1.

The API uses camel-case in JSON. The on-disk formats above use snake_case for top-level envelope fields and CSV headers, so a person can read them without a glossary.

## 7. Verdict (rules output)

```json
{
  "rule": "companion",
  "status": "pass",
  "placementId": "p_tomato",
  "neighborPlacementId": "p_marigold",
  "observed": 0.7,
  "required": "within 2.5 m",
  "message": "Tomato and French marigold: nematode suppression claimed (beneficial, evidence grade C)",
  "sourceId": "SRC-LORE",
  "grade": "C",
  "mechanism": "nematode_suppression_claimed",
  "direction": "beneficial"
}
```

`status` is one of `pass`, `warn`, `fail`, `unknown`. Rules: `graph_membership`, `hardiness`, `sun`, `soil_ph`, `footprint_overlap`, `spacing_same_species`, `mature_overlap`, `companion`.

## 8. Feedback log: `data/feedback/feedback.ndjson`

One JSON object per line, append-only, in the same chained style as section 1. The only event type is
`FeedbackRecorded`.

```json
{"seq":1,"ts":"2026-11-01T10:00:00.000Z","type":"FeedbackRecorded",
 "actor":{"id":"web","interface":"web"},"idempotency_key":"feedback-…",
 "payload":{"id":"fb_0123456789abcdef","designId":"d_…","placementId":"p_lavender",
            "rule":"sun","reasonTag":"site_condition_differs","note":"…",
            "graphVersion":"kg-2026.10","ruleConfigVersion":"rules-1.0","modelVersion":"none"},
 "prev_hash":"000…0","hash":"…"}
```

Hash: `sha256( prev_hash + "\n" + canonical_json({seq, ts, type, actor, idempotency_key, payload}) )`,
the same rule as section 1. `prev_hash` of seq 1 is 64 zeros.

Reason tags (closed list): `source_outdated`, `site_condition_differs`, `variety_differs`, `rule_too_strict`,
`rule_too_loose`, `data_wrong`, `other`.

Routes are computed when the feedback is read, from the reason tag. They are never stored. A route is a
suggestion for a person; see ADR-0007.

| Reason tag | Route |
|---|---|
| `source_outdated`, `data_wrong` | `curation_queue` |
| `rule_too_strict`, `rule_too_loose` | `rule_review` |
| `site_condition_differs` | `site_update` |
| `variety_differs`, `other` | `design_note` |

A torn final line is quarantined to `data/feedback/feedback.torn-<ms>-<id>.txt` on the next write.

## 9. Rule configuration: `config/rules/rules-<version>.json`

```json
{
  "version": "rules-1.0",
  "description": "…",
  "companionRadiusM": 2.5,
  "overlapToleranceM": 0.01,
  "matureOverlapWarnM": 0.25,
  "fallbackFootprintM": 0.5
}
```

`version` must match `rules-<major>.<minor>`. Every other field must be a positive number. The file is read at
start-up, and a bad file stops start-up. Results carry `version` as `ruleConfigVersion`. See ADR-0008.

## Migration rules

| From | To | Rule |
|---|---|---|
| Any log | Next version | Must replay under the new reducer to the same state, or be migrated by an ADR-approved step that is recorded as an event |
| Snapshot | Any | Discard and rebuild from the log if verification fails. Never trust an unverified snapshot. |
| Knowledge graph `kg-YYYY.MM` | Next month | Species URNs are stable. A retired species keeps a tombstone row. |
